# ДЗ 10. Фоновые задачи и кеширование

Взял проект из ДЗ 9 (CRUD студентов с входом по токену) и добавил:

- эндпоинт, который загружает в базу записи из csv по переданному пути, загрузка идет фоновой задачей
- эндпоинт, который удаляет записи по списку id, тоже фоновой задачей
- кеширование в Redis для всех эндпоинтов, которые отдают данные

Для фоновых задач взял `BackgroundTasks` из FastAPI, а не Celery: задачи короткие, и так не нужно поднимать отдельный воркер и брокер

## Как запустить

Нужен Redis. Проще всего через docker:

```bash
docker run -d -p 6379:6379 redis
```

Или `brew install redis` и `redis-server`. Потом:

```bash
pip install -r requirements.txt
python main.py
```

По умолчанию приложение идет в `redis://localhost:6379/0`, другой адрес можно задать через переменную `REDIS_URL`. Если Redis не запущен, приложение все равно работает, просто без кеша, в логе будет предупреждение

Как и раньше, при первом запуске создается `students.db` и в нее грузится `students.csv`. Документация: http://127.0.0.1:8000/docs, токен из `/auth/login` вставляется в кнопку Authorize

Тесты - `pytest`. Вместо настоящего Redis в них `fakeredis`, поэтому для тестов ничего поднимать не надо

## Новые эндпоинты

| Метод | Путь | Что делает |
|---|---|---|
| POST | `/students/import` | загрузить записи из csv, тело `{"path": "путь к файлу"}`, ответ 202 |
| POST | `/students/bulk-delete` | удалить записи, тело `{"ids": [1, 2, 3]}`, ответ 202 |

Оба доступны только вошедшему пользователю без `read_only`, как и остальные изменения. Остальные эндпоинты те же, что в ДЗ 9

## Как работает кеш

- Кешируются `GET /students/` (для каждого набора фильтров `faculty` и `course` свой ключ) и `GET /students/{id}`. Ключи в Redis начинаются с `students:`
- Ответ живет в кеше 60 секунд
- Любое изменение через api (создание, PUT, PATCH, удаление, фоновая загрузка и фоновое удаление) сбрасывает весь кеш студентов. Фоновые задачи сбрасывают кеш в конце, когда данные уже поменялись
- 404 не кешируется, запись может появиться позже
- Ответы `/auth` не кешируются: они не отдают данные из базы, а логин каждый раз выдает новый токен
- Если Redis упал, первый запрос ловит ошибку, и дальше 60 секунд (столько же, сколько живет кеш) приложение в Redis не ходит, чтобы запросы не ждали таймаут

## Как я понял неоднозначные места

- "Путь к csv-файлу" - это путь на машине, где запущен сервер, файл не загружается через запрос. Относительный путь считается от папки, из которой запущен сервер, поэтому надежнее передавать полный. Формат тот же, что у `students.csv`: колонки Фамилия, Имя, Факультет, Курс, Оценка
- Перед запуском задачи проверяю, что файл есть (иначе 404) и что в нем нужные колонки (иначе 422). Каждая строка проверяется так же, как данные в api: оценка от 0 до 100, строки не пустые. Если ошибка найдется уже в процессе загрузки, например оценка не число, ответ клиенту уже ушел. Тогда ошибка пишется в лог, а в базу не попадает ничего, потому что записи вставляются одним коммитом в конце
- Записи из csv добавляются к тем, что уже есть. Проверку на дубли не делал, в ДЗ 6 загрузка тоже просто добавляла строки
- В списке на удаление можно передать от 1 до 1000 id. Повторы убираются, id, которых нет, пропускаются, сколько реально удалилось - пишется в лог
- Ответ 202 значит "задача принята". Отдельного эндпоинта со статусом задачи не делал, в условии его нет
- Путь к файлу на сервере принимаю только от пользователя с правами на запись. В настоящем сервисе так делать не стоит, лучше загружать сам файл, но в задании просили именно путь

## Пример

```bash
curl -X POST http://127.0.0.1:8000/students/import \
  -H 'Authorization: Bearer <токен>' \
  -H 'Content-Type: application/json' \
  -d '{"path": "/tmp/more.csv"}'
```

Ответ 202: `{"detail": "Загрузка /tmp/more.csv запущена в фоне"}`, в логе сервера потом `Из /tmp/more.csv загружено записей: 2`

```bash
curl -X POST http://127.0.0.1:8000/students/bulk-delete \
  -H 'Authorization: Bearer <токен>' \
  -H 'Content-Type: application/json' \
  -d '{"ids": [1, 2, 3]}'
```

Ответ 202: `{"detail": "Удаление 3 записей запущено в фоне"}`

Если файла нет: 404 `{"detail": "Файл /tmp/nope.csv не найден"}`
